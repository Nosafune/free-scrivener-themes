# Compile Options

## Fast answer

Compile Options are export-level switches that control how Scrivener treats comments, annotations, titles, text, and other output behaviors.

## Why this matters


Compile Options are easy to overlook because they seem secondary.

They often determine whether output includes or excludes editorial material.

This area may affect:

- comments
- annotations
- titles
- synopses
- notes
- text transformations
- front matter behavior
- ebook-specific behavior


## Core workflow


Basic workflow:

1. Choose output type and format.
2. Review Contents.
3. Review Metadata.
4. Review Options.
5. Decide what editorial material should appear.
6. Compile a test.
7. Search output for comments, annotations, and draft markers.

For final output, be strict:

```text
No accidental comments.
No accidental annotations.
No draft-only notes.
No internal labels.
```


## Common mistakes


### Ignoring Options

Small checkboxes can create large output differences.

### Accidental comments

Never assume comments are excluded.

### Wrong behavior carried from previous compile

Review options before each serious export.

### No final search

Search compiled output for common internal markers.


## Practical test

Compile a small sample before compiling the full manuscript. Use one chapter, one scene, one front matter item, and one item that uses the setting being tested.

## Troubleshooting lens

When output looks wrong, ask:

1. Is the correct material included?
2. Is the correct Section Type assigned?
3. Is the correct Section Layout assigned?
4. Is the selected Compile Format the one being edited?
5. Is the output format capable of showing the thing you expect?


## Final-output search terms

Before sending a manuscript, search the compiled file for:

```text
TODO
CHECK
FIX
DRAFT
NOTE
???
[[
]]
comment
```

## Editorial export vs final export

An editorial export may intentionally include comments.

A final export almost never should.
